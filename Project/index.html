Core capabilities

Everything your hiring pipeline needs

Skill Extraction

Parses free-text resumes and job descriptions. Uses a HashSet to deduplicate skills and normalize to lowercase — no manual tagging needed.

O(n)

Edit Distance Fit Score

Wagner-Fischer Dynamic Programming computes fuzzy string alignment, handling typos, synonyms, and variations. Weighted scoring with must-have vs nice-to-have skills.

O(m·n)

Merge Sort Ranking

All candidates are sorted by score using Merge Sort. Top-K shortlisting uses a Max-Heap Priority Queue with animated visualization.

O(n log n)

Skill Gap Analysis

Shows exactly which skills a candidate has (matched) vs. which are missing, with "to reach 100% add: docker, sql" suggestions.

O(k)

Related Skills Graph

BFS on a skill graph gives partial credit — a candidate with React gets partial credit for JavaScript. Visualized as a node graph.

O(V+E)

Trie Autocomplete

Typing "ja" instantly suggests Java, JavaScript. Prefix-tree search is O(k) for any prefix length — fast, visual, and a classic DSA topic.

O(k) search

Pipeline

How matching works

01

Post a Job

Enter a job title and paste required skills. Mark each as "Must Have" or "Nice to Have" for weighted scoring. Use quick templates like "Frontend Dev" or "Data Analyst".

02

Add Candidates

Upload PDFs (drag & drop multiple) or paste resume text. SkillExtractor normalizes and deduplicates via a HashMap. Trie gives instant autocomplete.

03

Score

EditDistanceScorer computes Wagner-Fischer DP edit distance to fuzzy match skills. BFS on the skill graph awards partial credit for related skills.

04

Rank & Shortlist

CandidateRanker sorts by score using Merge Sort. Top-K uses a Max-Heap. Star candidates, add notes, compare side-by-side, and export CSV/PDF.

DSA Reference

Algorithms powering TalentMatch

HashMap / HashSet

SkillExtractor — O(n) skill normalization. Deduplication in constant time using hash-based sets (Module 1/6).

O(n) insert/lookup

Trie (Prefix Tree)

SkillTrie — O(k) skill autocomplete as you type. Powers the live suggestion dropdowns in job and candidate forms.

O(k) search

Edit Distance (Wagner-Fischer DP)

EditDistanceScorer — Dynamic programming sequence alignment (Module 3). Handles typos, variations, and fuzzy matching.

O(m·n) DP

Merge Sort

CandidateRanker — O(n log n) stable sort by score descending. Compared live against Quick Sort and Heap Sort in the analytics page.

O(n log n)

Max-Heap / Priority Queue

MaxHeap — Top-K shortlisting with O(log n) insert and extract. Animated heap tree shows each insert and heapify-up step.

O(log n) insert

Graph BFS

SkillGraph — Related-skills adjacency list. BFS gives partial credit (react→javascript). Visualized as an interactive node graph.

O(V+E)

LCS (Longest Common Subsequence)

LCSAnalyzer — Finds longest common phrases between a resume and a job description. Highlights matching terms in both texts.

O(m·n) DP

Weighted Scoring

WeightedScorer — Recruiters mark skills as Must-Have (weight 3) or Nice-to-Have (weight 1). Score = weighted sum / total possible weight.

O(k) per candidate

FAQ

Frequently asked questions

What DSA modules does TalentMatch cover?

TalentMatch covers Module 1 (HashMap/HashSet), Module 2 (Trie), Module 3 (Edit Distance DP, LCS), Module 4 (Merge Sort, Quick Sort, Heap Sort), Module 5 (Max-Heap Priority Queue), and Module 6 (Graph BFS). Every algorithm is used in a real, observable feature.

Does it need a backend / server?

No. All algorithms run in the browser in pure JavaScript. The optional Java backend (HttpServer on port 8080) adds server-side matching, but the app works fully offline without it.

Can it read any PDF resume?

TalentMatch uses PDF.js to extract text from digital PDFs. Scanned / image-only PDFs won't have selectable text — use the "Paste Resume Text" fallback in that case. You can drag & drop multiple PDFs at once.

How does the fuzzy skill matching work?

The Wagner-Fischer algorithm computes the Levenshtein edit distance between every candidate skill and every required job skill. A skill is considered matched if the normalized distance ≤ 35%, so "javascrpt" still matches "javascript".

What are "Weighted Skills"?

When creating a job, you can mark each skill as "Must Have" (weight 3) or "Nice to Have" (weight 1). The final score becomes a weighted sum — missing a must-have skill hurts far more than missing a nice-to-have. Rankings visibly change.

How does the related-skills graph work?

The SkillGraph module maintains an adjacency list (e.g. react → [javascript, typescript, redux]). A BFS from each candidate skill finds neighbours at depth 1 and awards 50% credit. A candidate who knows React gets partial credit for JavaScript even if they didn't explicitly list it.

Can I export results?

Yes. Export ranked results as a CSV file or as a formatted PDF report — useful for sharing with hiring managers or including in your project demo.

Is candidate data stored anywhere?

All data (jobs, candidates, scores, notes) is stored in your browser's localStorage only. Nothing is sent to a server. Use "Clear All Data" in the sidebar to reset.
